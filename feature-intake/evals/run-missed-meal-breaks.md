# Прогоны `feature-intake`

## Прогон 1 — размытая задача

**Вход, две фразы, как приходит в реальности:**

> Супервайзеру нужно видеть, кто из ассоциатов не взял meal break вовремя.
> Сделай отчёт.

### Фаза 2 — факты, найденные в коде

Четыре вопроса сняты чтением репозитория, ни один не задан человеку:

```
- FACT: роль называется Manager, не Supervisor — bb/models.py, bb/app/shift/models.py
        (Manager 61 вхождение, supervisor 3)
- FACT: meal break в модели два, не один — bb/app/shift/models.py:40-43
        signed_lunch1_start/end, signed_lunch2_start/end
- FACT: «вовремя» уже определено данными — bb/app/shift/models.py:40-43
        threshold_lunch1_start, threshold_lunch1_end, threshold_lunch2_*
- FACT: таймзона конвертируется утилитой convertDateTimeToCurrentTimeZone —
        whereami/src/views/active-associates.vue:122
```

Находка `threshold_*` — самая ценная. Заказчик сказал «вовремя», не зная, что в модели
уже лежит окно допустимого времени. Без чтения кода это стало бы вопросом, а потом
вторым определением «вовремя» рядом с существующим.

Находка «два meal break» переводит задачу из понятной в неоднозначную: `lunch1` и
`lunch2` — «не взял вовремя» относится к первому, второму или любому.

### Понятно
- нужен отчёт, экранный, для роли Manager
- источник данных — подписанные интервалы meal break против пороговых окон

### Неоднозначно
| Точка | Прочтения |
|---|---|
| «не взял вовремя» | (а) не взял вообще (б) взял позже окна (в) взял, но короче требуемого (г) любое из трёх |
| какой meal break | первый / второй / любой |
| «супервайзер» | Manager своей компании / Manager всех компаний |

### Вопросы — быстрый режим, лимит 3

```
- Q1 [blocker]: Какой meal break считается — первый, второй или любой?
- Q2 [blocker]: «Не вовремя» — это отсутствие, опоздание относительно threshold, или
  недостаточная длительность?
- Q3 [blocker]: Manager видит ассоциатов только своей компании или всех?
```

Все три блокирующие: при любом другом ответе отчёт покажет не тех людей. Четвёртый
вопрос был бы про статус смены — он ушёл в допущения.

### Допущения — всё, что за лимитом

```
- A1: отчёт покрывает только завершённые смены — цена ошибки: незавершённые требуют
  отдельного состояния и ещё одного запроса
- A2: диапазон дат выбирается так же, как в active-associates — цена ошибки: другой
  контрол, переделка фильтра
- A3: отчёт нужен только на web, не в мобильном приложении — цена ошибки: вся работа
  дублируется на Flutter, включая семь локалей
- A4: экспорт в Excel нужен, как во всех соседних отчётах — цена ошибки: лишний час
- A5: данные не уходят за пределы продукта — цена ошибки: если уходят, нужна проверка
  юристом на передачу данных о нарушениях трудового распорядка
```

### Скрытые требования — 6, ни одного не было в исходной формулировке

| # | Требование | Откуда |
|---|---|---|
| 1 | Права: что видит пользователь без роли Manager | чек-лист web, «Permissions» |
| 2 | Пустой результат: нарушений нет — это успех, а не пустота | чек-лист web, «Empty result» |
| 3 | Объём: компания на 10 000 ассоциатов, пагинация | чек-лист web, «Pagination» |
| 4 | Таймзона: чьё время — ассоциата, компании или смотрящего | чек-лист web, «Timezone» |
| 5 | Экспорт и печать: соседние отчёты это умеют, `print-js` в зависимостях | чек-лист web, «Export / Print» |
| 6 | **Юридическая чувствительность**: отчёт о нарушениях meal break — материал для дисциплинарных действий; в продукте есть `disciplinary` (53 строки) | чек-лист данных + `red-lines.md` |

Шестое — не из чек-листа механически, а из связи с красными линиями продукта. Отчёт
такого рода меняет статус данных: то, что собиралось для расчёта оплаты, начинает
использоваться для взысканий.

### Критерии приёмки

```
- AC1: Manager, открывший отчёт за диапазон дат, видит каждого ассоциата, у которого
  signed_lunch1_start вне окна threshold_lunch1_start..threshold_lunch1_end
- AC2: пользователь без роли Manager, открывший URL отчёта, видит экран no-permissions
- AC3: при отсутствии нарушений за период экран сообщает, что нарушений нет, и не
  показывает дефолтный No Data
- AC4: время в отчёте показано в той же таймзоне, что и в active-associates
```

Ни в одном нет слов `properly`, `correctly`, `as expected`.

### Скоуп
- **В скоупе:** web-отчёт, фильтр по датам, экспорт
- **Вне:** мобильная версия, уведомления Manager'у, автоматические дисциплинарные действия
- **Отложить без вреда:** печать, второй meal break если ответ на Q1 — «первый»

### Метрика успеха
- подтверждает пользу: доля смен с нарушением meal break падает в течение двух месяцев
- покажет вред: рост числа дисциплинарных записей без падения нарушений — значит отчёт
  используется для наказаний, а не для исправления процесса

### Данные
| Данные | Где | Кому передаются |
|---|---|---|
| подписанные интервалы meal break | `bb/app/shift/models.py` | Manager компании |
| идентификатор ассоциата | там же | Manager компании |

⚖️ Нужна проверка юристом: отчёт делает нарушения meal break видимыми для руководства.
В США это регулируемая зона трудового права.

### Раскладка работы
- запрос, сравнивающий подписанные интервалы с пороговыми окнами
- экран отчёта по образцу соседних отчётов
- проверка прав на маршруте
- экспорт
- состояние «нарушений нет»

Без чисел.

## Прогон 2 — невнятная жалоба

**Вход:** «Не работает кнопка».

**Выход — шаги воспроизведения вместо вопросов:**

Реконструкция из кода: кнопок, у которых есть состояние disabled и асинхронное действие,
в web-приложении немного. `active-associates.vue` даёт две — обе `:disabled="loading"`.
Наиболее вероятный сценарий: кнопка выглядит нерабочей, пока идёт запрос, а запрос упал
— тост исчез, `loading` снялся, но пользователь уже не понимает состояние экрана.

```
Шаги: 1) открыть отчёт  2) выбрать период  3) дождаться ошибки загрузки
      4) нажать кнопку экспорта
Ожидалось: экспорт или объяснение, почему он недоступен
Фактически: кнопка активна, но данных нет — экспортируется пустой файл
```

```
- Q1 [blocker]: на каком экране кнопка?
- Q2 [blocker]: что происходило непосредственно перед нажатием?
- Q3 [later]: web или мобильное приложение?
```
