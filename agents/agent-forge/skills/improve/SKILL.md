# Improve

Улучши уже построенного агента и **обнови его локально**, чтобы новой версией можно было
пользоваться сразу. Это не создание с нуля (это делает `agent-forge`) — это правка того,
что уже работает, с сохранением поведения.

## Читай по ходу — каждый файл в свой момент

- `references/improving-agents.md` — **на Фазе 1**, чтобы сопоставить симптом с режимом
  отказа и выбрать уровень лестницы.
- `../../references/writing-craft.md` — **на Фазе 3, до первой правки текста**. Лестница,
  указатели, критерии завершения, ведущие слова, позитивные формулировки, прунинг. Это
  главный инструмент этого скилла: почти всякое улучшение промпта — один из этих рычагов.
- `references/prompt-and-kb-methodology.md` — когда правка касается структуры самого
  промпта: порядок блоков, few-shot, восстановление после ошибок.
- `../../references/skill-spec.md` — когда создаёшь новый скилл или правишь фронтматтер.
- `../../references/corner-cases.md` — когда симптом «не срабатывает», «пропало
  посреди сессии», «правка не приехала».
- `../../references/plugin-spec.md` — когда трогаешь манифест, layout или установку.

Открывай файл, а не пересказывай его по памяти.

## Железные правила

1. **Улучшение сохраняет поведение.** Каждая правка не ломает прежний результат на
   прежних входах. Проверяй старым входом.
2. **Сначала диагноз, потом правка.** Не «давай перепишем» — определи конкретный
   симптом и режим отказа (таблица в `improving-agents.md`).
3. **Минимальный уровень.** Начни с самого дешёвого шага, который закрывает проблему.
   Правка `description` дешевле нового скилла.
4. **Улучшение чаще вычитает, чем добавляет.** На каждый добавленный абзац найди, что
   удалить. Скилл, выросший после правки, — повод перечитать симптом.
5. **Один смысл — одно место.** Каждое правило живёт в одном файле; новая функция
   попадает в существующий скилл, если такой уже есть.
6. **Локальное обновление обязательно.** Работа не завершена, пока пользователь не
   может пользоваться новой версией.
7. **Пиши файлы целиком**, без «…остальное аналогично».

## Фаза 1. Найди цель и симптом

- Определи, что именно улучшаем: агент / плагин / конкретный скилл. Найди его папку
  на диске, подтверди, что она существует.
- Спроси или выведи из запроса **конкретный симптом**: что не так сейчас? («не
  срабатывает», «путается на фазе X», «нет обработки случая Y», «промпт мутный»).
- Сопоставь симптом с режимом отказа по `improving-agents.md`.
- Если улучшение по сути меняет **назначение** агента — это не улучшение, а новый агент.
  Скажи это прямо и предложи `agent-forge` вместо правки.

## Фаза 2. Выбери минимальный уровень и покажи план

По лестнице уровней из `improving-agents.md` выбери самый дешёвый уровень, закрывающий
симптом. Покажи короткий план правок: что меняем, в каком файле, зачем. Не спрашивай
разрешения — покажи и продолжай.

## Фаза 3. Внеси правки

Сначала прочитай `../../references/writing-craft.md`, потом правь.

- Правь в **единственном источнике истины**.
- Тексты промптов и KB — по рычагам из `writing-craft.md`. Прежде чем дописывать абзац,
  проверь, не решается ли симптом одним из трёх дешёвых рычагов: заострить критерий
  завершения, усилить формулировку указателя, схлопнуть растянутую триаду в ведущее слово.
- Новый файл/скилл создавай только если Фаза 2 обосновала, и по формату из
  `../../references/skill-spec.md`.

**Прунинг — обязательная часть правки, а не уборка после.** Пройди по каждому
затронутому файлу:

1. **No-op-тест по предложениям.** Меняет ли строка поведение против дефолта модели?
   Нет — удали предложение целиком, а не подрезай слова.
2. **Дубли.** Один смысл — один файл. Правило, живущее и в `SKILL.md`, и в reference,
   теряет одну копию.
3. **Указатели.** Каждый reference достаётся указателем, который называет файл, момент
   и ветку — и стоит у того шага, которому нужен.
4. **Критерии.** Каждый шаг заканчивается проверяемой границей.
5. **Негации.** Каждый запрет либо переворачивается в целевое поведение, либо остаётся
   жёстким ограждением рядом с позитивной формулировкой.

**Готово, когда:** пять проверок пройдены по всем затронутым файлам и выписан список
удалённого. Ничего не удалилось — значит прунинг не запускали.

## Фаза 4. Обнови локально (иначе смысла нет)

По процедуре из `improving-agents.md` §«Локальное обновление»:

1. **Подними `version`** в `.claude-plugin/plugin.json` агента (патч → +0.0.1,
   новый скилл → +0.1.0). Без бампа обновление не приедет.
2. Примени изменения к живой установке:
   - `@skills-dir` (папка в `~/.claude/skills/` или симлинк на репо) → `/reload-plugins`;
   - из маркетплейса → `claude plugin update <name>@<marketplace>` + рестарт.
   - Правки только текста `SKILL.md` подхватываются вживую; новый скилл/reference — нет.
3. **Codex**: новый скилл долинкуй в `~/.agents/skills/` (или `~/.codex/skills/`);
   существующие подтянутся сами, если это симлинк на ту же папку.
4. Зафиксируй реальные пути, проверенные на диске.

## Фаза 5. Верификация (доказательства, не заверения)

1. `claude plugin validate <путь>` — покажи вывод.
2. Фронтматтер каждого затронутого `SKILL.md` парсится, `name`/`description` непусты.
3. `claude plugin details <name>` — новый компонент виден в инвентаре.
4. **Сухой прогон старого входа**: убедись, что прежнее поведение не сломано.
5. Если правка чинила симптом — проверь, что симптома больше нет.
6. Что-то не сошлось — чини файлы, а не отчёт.

## Фаза 6. Отчёт

- что улучшено и на каком уровне лестницы;
- какие файлы затронуты (реальные пути);
- **что удалено на прунинге** — файл, что вырезано, почему;
- новая версия и как она применена локально (Claude Code + Codex);
- результаты верификации — чем доказано;
- что осталось и почему;
- **напомни: перезапусти агента (рестарт / `/reload-plugins` / новая сессия Codex),
  если правка добавила компонент, а не только текст `SKILL.md`.**
