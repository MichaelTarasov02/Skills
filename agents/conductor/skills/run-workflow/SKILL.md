# Run Workflow

Запусти долгий многоагентный прогон, который уходит работать и возвращается с готовым
результатом.

**Вызов этого скилла — и есть явное согласие на оркестрацию.** Контракт инструмента
Workflow признаёт скилл, чьи инструкции предписывают его вызвать, наравне со словом
`ultracode`. Дальше по процедуре — без переспрашивания, нужен ли конвейер.

## Чем платишь — скажи это до запуска

Конвейер — это фан-аут сабагентов. Каждый стартует со своим контекстом, и расход растёт
по числу агентов, а не по объёму задачи. Замеренный прогон на четыре домена: **11 агентов,
1.1 млн токенов, 13 минут**. Отменить сабагентов нельзя — на них держится и параллельность,
и независимость проверки.

Назови порядок цифры до запуска. Прогон, чья стоимость выяснилась постфактум, — плохой
прогон, даже если результат хорош.

## Читай по ходу

- `../../references/workflow-authoring.md` — **на Шаге 4, до первой строки скрипта**:
  скелет `meta`, функции тела, правило барьера, схемы, пределы, возобновление, приёмы
  качества.

## Шаг 1. Проверь форму задачи

Конвейер оправдан, когда верно хотя бы одно:

- **много однотипных единиц** — домены, файлы, модули, находки;
- **нужна независимая проверка** — проверяющий не должен видеть, как собирали, иначе он
  подтвердит собственные ошибки;
- **объём не помещается в один контекст** — не по трудозатратам, а по тому, что нужно
  держать одновременно.

Задача решается одним проходом — скажи это и сделай напрямую. Один вызов дешевле
конвейера на два порядка.

**Готово, когда:** названо, какое из трёх условий выполняется, либо принято решение
работать без конвейера.

## Шаг 2. Разведай очередь **до** написания скрипта

Скрипт не имеет доступа к файловой системе: файлы читают агенты. Значит очередь работы
собирается **здесь, обычными инструментами** — перечисли домены, найди файлы, вычисли
диапазон правок.

Это и есть гибридный путь: разведка вживую, затем конвейер по найденному. Форму задачи
знать заранее не нужно — нужно знать её до шага оркестрации.

**Готово, когда:** очередь существует как конкретный список, и каждый её элемент проверен
на диске.

## Шаг 3. Согласуй размер и бюджет

- **Размер.** Соблюдай ограничение размера, действующее в сессии; при отсутствии явного —
  держись под 15 агентами. Больше — спроси.
- **Бюджет.** Пользователь задал потолок — используй `budget` в скрипте: цикл «работай,
  пока остаётся больше N» точнее фиксированного числа итераций. Потолка нет — назови
  ожидаемое число агентов и порядок токенов, и продолжай.
- **Урезал охват** — скажи об этом через `log()` внутри прогона. Молчаливое усечение
  читается как полное покрытие.

## Шаг 4. Напиши скрипт

По `../../references/workflow-authoring.md`. Три решения, которые определяют всё
остальное:

1. **`pipeline` или `parallel`** — правило барьера в справочнике; по умолчанию `pipeline`.
2. **Схемы вместо длинных промптов** для всего, что должно вернуться обязательно.
3. **Детерминированность** — источники недетерминированности перечислены в справочнике.

Передавай скрипт полем `script` прямо в вызове. Каждый вызов сам сохраняет скрипт в файл и
возвращает путь.

**Готово, когда:** `meta` — чистый литерал, заголовки фаз совпадают с вызовами `phase()`,
и в скрипте нет запрещённых источников недетерминированности.

## Шаг 5. Запусти

Вызови инструмент **Workflow**. Он возвращается сразу с идентификатором прогона, а
уведомление приходит по завершении; живой прогресс пользователь смотрит через
`/workflows`.

Пока прогон идёт — занимайся тем, что от него не зависит, либо жди. Не выдумывай его
результаты: уведомление приходит само и никогда не пишется тобой. Спросили до его
прихода — скажи, что прогон ещё идёт.

## Шаг 6. Возобновление — вместо перезапуска

Прогон прерван, упал или скрипт поправлен — вызывай снова с `scriptPath` и
`resumeFromRunId`. Перезапуск без него оплачивает весь прогон заново.

**Готово, когда:** при повторном запуске указан `resumeFromRunId` прошлого прогона.

## Шаг 7. Отчитайся по факту, а не по замыслу

Прогон вернул пустоту или странность — **прочитай `journal.jsonl`** прежде, чем
объяснять. Кэшированный результат не обязан быть непустым: проверь, а не предполагай.

В отчёт:

- что сделано и чем это доказано;
- сколько агентов, токенов и времени ушло — по факту прогона;
- что урезано или не покрыто;
- путь к сохранённому скрипту.

## Шаг 8. Сохрани то, что стоит повторять

Прогон, который понадобится снова, переезжает в `.claude/workflows/` проекта — оттуда он
вызывается **по имени**, а не по пути, и становится частью проекта, а не артефактом
сессии.

## Жёсткие правила

- Стоимость называется до запуска, а не после.
- Очередь работы собирается вживую до оркестрации: скрипт файлов не читает.
- По умолчанию `pipeline`; барьер обосновывается вслух.
- Повторный запуск идёт через `resumeFromRunId`.
- Результат прогона берётся из журнала. Пока уведомление не пришло, прогон идёт.
- Задача, решаемая одним проходом, решается одним проходом.
