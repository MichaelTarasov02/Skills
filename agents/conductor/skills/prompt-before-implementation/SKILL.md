# Prompt Before Implementation

Преврати сырой запрос в **мощный промпт с пятью обязательными фазами**, покажи его,
подбери скиллы под каждую фазу и **выполни**.

Промпт создаётся не для ручного ввода: пользователь его лишь одобряет, исполняешь ты.
Поэтому промпт обязан работать без человека в цикле.

Это глубокий путь. Отличие от `suggest-skills` — шаги карты контекста и написания
промпта перед работой. Если запрос и так ясен, используй `suggest-skills`.

**Терминология:** **Шаг** — что делаешь ты. **Фаза** — что содержит промпт. Их ровно пять.

## Читай перед работой

- `references/prompt-blueprint.md` — обязательный каркас промпта, пять фаз, формат
  контекстной карты. Читай на Шаге 1, до написания промпта.
- `references/skill-selection.md` — правила подбора скиллов и режим пробела.
- `references/output-format.md` — формат плана, отбивок и журнала.

## Шаг 1. Разбери намерение и построй карту контекста

Сначала про себя:

1. Какой **реальный исход** нужен, а не буквальная формулировка?
2. Каким способом он достигается? Есть ли способ лучше названного?
3. Что считается «готово» — измеримый критерий?
4. Что подразумевается, но не сказано (стек, формат, объём, аудитория)?

Затем — **обход knowledge и карта контекста**. Это не опционально: карта войдёт
в промпт и сократит обращения к файлам на всех последующих фазах.

- Пройдись по знаниям, связанным с запросом: файлы проекта, документация, прошлые
  артефакты, релевантные скиллы и их `references/`.
- Классифицируй найденное по четырём уровням из `references/prompt-blueprint.md`:
  **Must See** (без этого результат неверен) · **Should See** (для полноты) ·
  **Already Have** (уже прочитано, не открывать снова) · **Uncertainties**.
- На каждый файл — обоснование одной фразой. Путь без «зачем» — это шум.
- **Прочитай только Must See.** Should See оставь на потом: в этом и экономия.
- Проверяй существование пути прежде, чем вносить его в карту.

Больше 5–7 файлов в Must See означает, что задача не сужена. Вернись к разбору.

**Режим.** Глубокий режим включается словами «комплексная», «сложная», «большая»,
«исчерпывающий», «на новый уровень», «критически важно», либо объективной
многоэтапностью. Пять фаз обязательны в любом режиме; в глубоком они дополняются
чекпоинтами внутри фазы 2.

## Шаг 2. Вопросы — максимум 2–3

Задавай только те, ответ на которые **изменит результат**: развилка подхода,
недостающий вход, взаимоисключающие трактовки. Остальное прими как допущение и пометь.

**Не блокируйся.** Даже задав вопросы, ты обязан в этом же ответе выдать промпт на
явно помеченных допущениях. Пользователь сам решит — ответить или забрать как есть.

## Шаг 3. Напиши промпт

Строго по каркасу из `references/prompt-blueprint.md`: восемь разделов, встроенная
контекстная карта из Шага 1 и пять фаз — Брейншторм → План → Имплементация →
Тестирование → Отчёт.

Пять фаз накладываются **всегда**. Задача почти не требует фазы — сожми её до строки,
но не выбрасывай.

Промпт должен быть понятен «холодному» исполнителю без вашей переписки.

## Шаг 4. Подбери скиллы под фазы промпта

По `references/skill-selection.md`. Подбираешь не под сырой запрос, а под **пять фаз
написанного промпта** — они точнее. Один скилл на фазу, без дублей.

## Шаг 5. Гейт пробела

Нет скилла под важную фазу — остановись, предложи установку, дождись ответа, затем
вернись ровно к тому месту, где остановился.

## Шаг 6. Покажи промпт и план

```
📋 Что понял
- Цель: …
- Готово, когда: …

🗺 Контекстная карта
<Must See / Should See / Already Have / Uncertainties>

⚠️ Допущения · ❓ Вопросы (0–3, если есть)

📝 Промпт
<код-блок: восемь разделов, пять фаз>

🎼 План
<таблица фаза → скилл → зачем>
```

Затем **сразу продолжай выполнение**. Не жди подтверждения: пользователь остановит сам.

## Шаг 7. Выполни промпт

Иди по пяти фазам собственного промпта с отбивками. Скиллы **применяй**, а не упоминай.

Соблюдай карту: не открывай `Already Have` заново, `Should See` читай только при
реальной необходимости.

## Шаг 8. Верификация и журнал

Фаза 4 промпта уже требует доказательств — сверь результат с критериями приёмки
фактами, не заверениями. Затем журнал по `references/output-format.md`.

## Жёсткие правила

- Пять фаз в промпте всегда. Сжать можно, выбросить нельзя.
- Промпт — инструмент, не самоцель. Не длиннее самой работы.
- Карта контекста строится до написания промпта и содержит только существующие пути.
- Всегда выдавай промпт, даже при незакрытых вопросах.
- Максимум 3 вопроса.
- Не выдумывай скиллы и файлы.
- Не ставь два скилла с одной функцией в один план.
- Ничего не устанавливай без явного «да».
