# Prompt Before Implementation

Преврати сырой запрос в **мощный промпт с пятью обязательными фазами**, вооружи каждую
фазу скиллами, покажи промпт и **выполни**.

Промпт создаётся не для ручного ввода: пользователь его лишь одобряет, исполняешь ты.
Поэтому промпт обязан работать без человека в цикле — включая то, какие скиллы
применяются на каждой фазе.

Это глубокий путь. Отличие от `suggest-skills` — карта контекста и написание промпта до
работы. Если запрос и так ясен, используй `suggest-skills`.

**Терминология:** **Шаг** — что делаешь ты. **Фаза** — что содержит промпт. Их ровно пять.

## Читай по ходу — каждый файл в свой момент

- `../../references/prompt-blueprint.md` — **на Шаге 1**, до написания промпта: каркас,
  пять фаз, формат контекстной карты и карты скиллов.
- `../../references/skill-selection.md` — **на Шаге 4**, до первого названного скилла:
  процедура обзора библиотеки и правила подбора.
- `../../references/install-flow.md` — **на Шаге 5**, как только появился кандидат на
  установку: планка доверия и порядок возврата в работу.
- `../../references/output-format.md` — **на Шаге 6**, формат плана, отбивок и журнала.

## Шаг 1. Разбери намерение и построй карту контекста

Сначала про себя:

1. Какой **реальный исход** нужен, а не буквальная формулировка?
2. Каким способом он достигается? Есть ли способ лучше названного?
3. Что считается «готово» — измеримый критерий?
4. Что подразумевается, но не сказано (стек, формат, объём, аудитория)?

Затем — **обход knowledge и карта контекста**. Карта войдёт в промпт и сократит
обращения к файлам на всех последующих фазах.

- Пройдись по знаниям, связанным с запросом: файлы проекта, документация, прошлые
  артефакты.
- Классифицируй найденное по четырём уровням из `../../references/prompt-blueprint.md`:
  **Must See** · **Should See** · **Already Have** · **Uncertainties**.
- На каждый файл — обоснование одной фразой. Путь без «зачем» — это шум.
- **Прочитай только Must See.** Should See оставь на потом: в этом и экономия.
- Проверяй существование пути прежде, чем вносить его в карту.

Больше 5–7 файлов в Must See означает, что задача не сужена. Вернись к разбору.

**Режим.** Глубокий включается словами «комплексная», «сложная», «большая»,
«исчерпывающий», «на новый уровень», «критически важно», либо объективной
многоэтапностью. Пять фаз обязательны в любом режиме; в глубоком они дополняются
чекпоинтами внутри фазы 2.

**Готово, когда:** карта построена, все пути в ней существуют, Must See прочитан.

## Шаг 2. Вопросы — максимум 2–3

Задавай только те, ответ на которые **изменит результат**: развилка подхода,
недостающий вход, взаимоисключающие трактовки. Остальное прими как допущение и пометь.

**Не блокируйся.** Даже задав вопросы, выдай промпт в этом же ответе на явно помеченных
допущениях. Пользователь сам решит — ответить или забрать как есть.

## Шаг 3. Напиши промпт

Строго по каркасу из `../../references/prompt-blueprint.md`: восемь разделов, встроенная
контекстная карта и пять фаз — Брейншторм → План → Имплементация → Тестирование → Отчёт.

Пять фаз накладываются **всегда**. Задача почти не требует фазы — сожми её до строки,
но оставь на месте.

Промпт должен быть понятен «холодному» исполнителю без вашей переписки.

## Шаг 4. Вооружи каждую фазу скиллами

По `../../references/skill-selection.md`. Подбираешь не под сырой запрос, а под **пять
фаз написанного промпта** — они точнее.

Обзор ведётся **пофазно**: для каждой из пяти фаз ищешь по каталогу словами этой фазы,
затем смотришь соседей найденного кандидата по графу. Пять фаз — пять обзоров, а не один
общий.

На фазу — от одного до трёх скиллов с разными функциями, по правилам подбора из
`skill-selection.md`.

Готовую раздачу **впиши в промпт**, к соответствующим фазам: промпт исполняется без тебя,
и скиллы должны быть в нём, а не только в твоей голове.

**Готово, когда:** по всем пяти фазам проведён обзор, у каждого выбранного скилла названы
фаза и функция, раздача внесена в текст промпта.

## Шаг 5. Доустановка недостающего

Фаза без подходящего скилла — и фаза, где установленный заметно слабее
специализированного, — оба случая повод предложить установку.

По `../../references/install-flow.md`: прошло планку доверия — ставь сам и продолжай;
не прошло — покажи и дождись ответа. После установки прочитай установленный `SKILL.md`,
внеси скилл в промпт и **вернись ровно туда, где остановился**.

## Шаг 6. Покажи промпт и план

```
📋 Что понял
- Цель: …
- Готово, когда: …

🗺 Контекстная карта
<Must See / Should See / Already Have / Uncertainties>

⚠️ Допущения · ❓ Вопросы (0–3, если есть)

📝 Промпт
<код-блок: восемь разделов, пять фаз, скиллы внутри фаз>

🎼 План
<таблица фаза → скиллы → зачем; установленное помечено>
```

Затем **сразу продолжай выполнение**. Не жди подтверждения: пользователь остановит сам.

## Шаг 7. Выполни промпт

Иди по пяти фазам собственного промпта с отбивками. Скиллы **применяй**, а не упоминай.

Соблюдай карту: не открывай `Already Have` заново, `Should See` читай при реальной
необходимости.

## Шаг 8. Верификация и журнал

Фаза 4 промпта требует доказательств — сверь результат с критериями приёмки фактами.
Затем журнал по `../../references/output-format.md`, отдельной строкой — что установлено.

## Жёсткие правила

- Пять фаз в промпте всегда. Сжать можно, оставить нужно.
- Промпт — инструмент, не самоцель. Не длиннее самой работы.
- Карта контекста строится до написания промпта и содержит только существующие пути.
- Всегда выдавай промпт, даже при незакрытых вопросах.
- Максимум 3 вопроса.
- Проверяй существование скилла и файла, прежде чем называть.
- Не ставь в одну фазу два скилла с одной функцией.
- Ставь сам только прошедшее планку доверия; остальное — через явное «да».
