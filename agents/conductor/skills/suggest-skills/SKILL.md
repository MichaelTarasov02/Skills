# Suggest Skills

Подбери скиллы под запрос и **выполни его**, показывая, какой скилл работает на каждой
фазе. Недостающее — доставь сам.

Это быстрый путь: разобрал → подобрал → доставил недостающее → сделал. Нужна ещё фаза
написания промпта — это `prompt-before-implementation`.

## Читай по ходу — каждый файл в свой момент

- `../../references/skill-selection.md` — **на Фазе 2, до первого названного скилла**:
  процедура обзора библиотеки, правила подбора, когда включается режим пробела.
- `../../references/install-flow.md` — **на Фазе 3, как только появился кандидат на
  установку**: планка доверия и порядок возврата в работу.
- `../../references/output-format.md` — **на Фазе 4**, формат плана, отбивок и журнала.

## Фаза 1. Разбери запрос

Про себя ответь:

1. Какой **исход** нужен, а не буквальная формулировка?
2. Из каких **фаз работы** он состоит? Это скелет плана.
3. Что считается «готово»?
4. Задача нетривиальная? Простой вопрос или правка в одну строку — **сделай напрямую**
   и скажи, что скиллы не понадобились.

**Готово, когда:** фазы выписаны и по каждой понятно, что она производит.

## Фаза 2. Обзор библиотеки и подбор

По `../../references/skill-selection.md`. Сначала обзор, потом подбор — в этом порядке.

Пройди по каждой фазе: поиск по каталогу словами задачи, затем соседи найденного
кандидата по графу. Соседи важны: там лежат скиллы, которые работают в паре с найденным
и которых поиск по словам не достаёт.

На фазу — от одного до трёх скиллов, каждый со **своей функцией**. Два скилла с одной
работой в одной фазе — ошибка подбора.

**Готово, когда:** по каждой фазе выполнен поиск и просмотрены соседи, а у каждого
выбранного скилла названы его фаза и его функция.

## Фаза 3. Доустановка недостающего

Режим пробела включается и когда скилла нет, и когда установленный закрывает фазу
заметно хуже специализированного. Оба случая — повод предложить.

Дальше по `../../references/install-flow.md`: кандидат прошёл планку доверия — ставь сам
и продолжай; не прошёл — покажи и дождись ответа. После установки прочитай установленный
`SKILL.md` и **вернись ровно туда, где остановился**.

**Готово, когда:** каждая фаза либо обеспечена скиллом, либо явно помечена как идущая без
специализированного инструмента.

## Фаза 4. Покажи план

Таблица «фаза → скиллы → зачем» по `../../references/output-format.md`. Установленное в
этот заход помечай. Показал — продолжай; пользователь остановит, если нужно.

## Фаза 5. Выполни

Иди по фазам. Перед каждой — однострочная отбивка с именами применяемых скиллов.

**Скилл нужно применить**, а не упомянуть: вызови его и следуй его инструкциям.
Упоминание без применения — ложный отчёт.

Выяснилось по ходу, что фаза лишняя или нужна новая — скажи и обнови план. План служит
работе.

**Готово, когда:** каждая фаза плана выполнена, и по каждой видно, какой скилл сработал.

## Фаза 6. Журнал

Итоговая таблица «скилл → фаза → что дал» по `../../references/output-format.md`,
отдельной строкой — что было установлено и откуда.

## Жёсткие правила

- **Работа важнее отчёта.** План и журнал длиннее результата — сделал не то.
- Не называй количество скиллов в библиотеке — она растёт.
- Проверяй, что папка `<id>/SKILL.md` существует, прежде чем называть скилл.
- Не ставь в одну фазу два скилла с одной функцией.
- Ставь сам только то, что прошло планку доверия из `install-flow.md`; остальное — через
  явное «да». Отказ пользователя действует на всю сессию.
- Каждая установка попадает в журнал.
