# Правила подбора скиллов

Единый источник правил для обоих скиллов conductor. Не дублируй их в `SKILL.md` —
читай отсюда.

## Хост

Синтаксис вызова зависит от того, где ты работаешь:

| Хост | Вызов |
|---|---|
| Claude Code | `/имя-скилла` |
| Codex | `$имя-скилла` |

Определи хост и в выводе указывай вызов в правильном синтаксисе.

## Источники (сверяйся, НЕ выдумывай)

Библиотека пользователя постоянно расширяется. **Никогда не полагайся на фиксированное
число скиллов и не называй его.** Источник истины — папки на диске.

1. **Живая библиотека** (главный источник): папки `*/SKILL.md`. Ищи в порядке:
   - корень репозитория со скиллами, если работаешь внутри него (там же лежит `0-main/`);
   - `~/.agents/skills/` — общая папка, её читают и Claude Code, и Codex;
   - `~/.claude/skills/` и `~/.codex/skills/` — хосто-специфичные;
   - скиллы установленных плагинов (`<plugin>/skills/<name>/SKILL.md`).

   У каждого во frontmatter есть `name` и `description` — по ним и подбирай.

2. **`0-main/SKILLS_CHEATSHEET.md`** (если доступен) — кураторские best-of-breed по
   сферам и **таблица дедупликации**: когда несколько скиллов делают одно, там указан
   победитель. Это снимок, он может отставать — сверяй с живой библиотекой.

3. **`0-main/graph.json`** (если доступен) — связи между скиллами и центральность.

**Перед тем как назвать скилл, убедись, что его папка с `SKILL.md` реально существует.**

## Как подбирать

1. Раздели задачу на **фазы работы** — что именно предстоит сделать по шагам.
2. На каждую фазу подбери **один** скилл. Одна фаза — один скилл.
3. **Убери дубли.** Если два кандидата делают по сути одно и то же, оставь одного
   лучшего: сначала по таблице дедупликации из cheat sheet, при её отсутствии — по
   центральности в графе и популярности.
4. Ранжируй по: релевантность фазе → центральность → популярность.
5. **Не добивай до числа.** Если задаче хватает одного скилла — бери один. Лишний
   скилл вредит: он тратит контекст и уводит в сторону.
6. Не бери скилл «на всякий случай». У каждого должна быть своя фаза.

## Типовые фазы и что на них обычно нужно

Ориентир, не догма. Всегда проверяй наличие скилла в библиотеке.

| Фаза | Что там обычно уместно |
|---|---|
| Ресёрч перед решением | скилл многоисточникового исследования |
| Стресс-тест плана | скилл допроса допущений |
| Исполнение многошагового плана | скилл пошагового исполнения с чекпоинтами |
| Независимые параллельные части | скилл диспетчеризации агентов |
| Большой объём вывода | скилл запрета плейсхолдеров и обрывов |
| Текст для людей | скилл очистки от AI-паттернов |
| Завершение работы | скилл верификации доказательствами |

## Режим пробела: нужного скилла нет

Включается, когда для важной фазы в библиотеке нет подходящего скилла — не когда
«хотелось бы ещё один».

1. Честно скажи: «Из установленного фазу N закрывает только `X`, и он закрывает её
   частично» — либо «для фазы N подходящего скилла нет».
2. Сходи в каталог **https://www.skills.sh/** и подбери 1–3 недостающих скилла.
   Бери реальные записи с корректным `owner/repo`, приоритет — по числу установок.
3. Выдай предложение в таком виде:

   **Не хватает для фазы «N»:**
   - **`owner/repo`** (`skill-id`) — что делает и зачем именно здесь.
     Установка: `npx skills add owner/repo`

4. Спроси прямо: **«Установить их и продолжить, или работаем тем, что есть?»**
   Остановись и жди ответа.
5. После установки — **вернись к выполнению задачи с того места, где остановился**,
   и включи новый скилл в план фаз.

Если пользователь отказался — продолжай тем, что есть, и отметь в плане, какая фаза
осталась без специализированного инструмента.

## Жёсткие запреты

- Не выдумывай `skill-id` и `owner/repo`.
- Не называй количество скиллов в библиотеке.
- Не ставь два скилла с одной функцией в один план.
- Не устанавливай ничего без явного «да» пользователя.
