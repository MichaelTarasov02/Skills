# Правила подбора скиллов

Единый источник правил для обоих скиллов conductor. Читай отсюда, а не по памяти.

## Хост

| Хост | Вызов |
|---|---|
| Claude Code | `/имя-скилла` |
| Codex | `$имя-скилла` |

Определи хост и в выводе указывай вызов в правильном синтаксисе.

## Шаг 1. Обзор библиотеки — до того, как что-то предлагать

Библиотека постоянно растёт. **Никогда не полагайся на память о её составе и не называй
её размер.** Источник истины — диск.

Порядок обзора, от дешёвого к дорогому:

1. **Каталог.** `0-main/.skill_catalog.json` — плоский список всех скиллов с описаниями,
   по записи `{folder, name, desc}`. Он для поиска, а не для чтения целиком: грепай по
   словам задачи.

   Пути ниже отсчитываются от корня репозитория со скиллами. Работаешь в другом проекте —
   подставь абсолютный путь до него; каталога нет вовсе — переходи к пункту 3.

   ```bash
   python3 -c "
   import json,sys
   q=sys.argv[1].lower()
   for s in json.load(open('0-main/.skill_catalog.json')):
       if q in (s['folder']+s['name']+s['desc']).lower(): print(s['folder'],'—',s['desc'][:110])
   " <слово-из-задачи>
   ```

2. **Соседи по графу.** `0-main/graph.json` — связи между скиллами. Нашёл один
   подходящий → возьми его соседей: там лежат те, что работают в паре с ним и которых
   поиск по словам не находит.

   ```bash
   python3 -c "
   import json,sys
   n=sys.argv[1]; g=json.load(open('0-main/graph.json'))
   nb=sorted({l['target'] if l['source']==n else l['source']
              for l in g['links'] if n in (l['source'],l['target'])})
   print(len(nb),'соседей:',', '.join(nb))
   " <имя-скилла>
   ```

3. **Живые папки** — если каталог недоступен или устарел: `*/SKILL.md` в корне
   репозитория со скиллами, затем `~/.agents/skills/`, `~/.claude/skills/`,
   `~/.codex/skills/`, затем скиллы установленных плагинов.

4. **`0-main/SKILLS_CHEATSHEET.md`** — кураторские best-of-breed по сферам и таблица
   дедупликации: когда несколько скиллов делают одно, там назван победитель. Это снимок,
   он отстаёт от живой библиотеки — сверяй.

**Готово, когда:** по каждой фазе задачи выполнен поиск по каталогу и просмотрены соседи
хотя бы одного найденного кандидата. Обзор из одного грепа — это не обзор.

## Шаг 2. Как подбирать

1. Раздели задачу на **фазы работы**.
2. На каждую фазу подбери **от одного до трёх** скиллов — по одному на каждую **отдельную
   функцию**, которая на этой фазе нужна. Типичная тройка: процессный скилл задаёт метод,
   доменный приносит предметные знания, форматный держит вид результата.
3. **Разные функции — обязательное условие.** Два скилла, делающие одну работу, — ошибка
   подбора: оставь лучшего по таблице дедупликации из cheat sheet, при её отсутствии — по
   центральности в графе и числу установок.
4. Ранжируй по: релевантность фазе → центральность в графе → популярность.
5. **Каждый скилл в плане отрабатывает свою фазу.** Скилл, которому не нашлось конкретной
   работы, тратит контекст и уводит в сторону — такому место вне плана.
6. Одной фазе честно хватает одного скилла — ставь один. Добивать до трёх незачем.

**Готово, когда:** у каждого скилла в плане названа его фаза и его функция, и никакие два
скилла в одной фазе не делят одну функцию.

## Типовые фазы и что на них обычно нужно

Ориентир, не догма. Наличие скилла проверяй по каталогу.

| Фаза | Что там обычно уместно |
|---|---|
| Ресёрч перед решением | многоисточниковое исследование + предметный скилл по теме |
| Стресс-тест плана | допрос допущений |
| Исполнение многошагового плана | пошаговое исполнение с чекпоинтами + доменный скилл стека |
| Независимые параллельные части | диспетчеризация агентов |
| Большой объём вывода | запрет плейсхолдеров и обрывов |
| Текст для людей | очистка от AI-паттернов + доменный скилл жанра |
| Завершение работы | верификация доказательствами |

## Шаг 3. Режим пробела — когда предлагать установку

Включается в двух случаях, а не только в одном:

- **Пробел.** Для важной фазы в библиотеке нет подходящего скилла.
- **Частичное покрытие.** Установленный скилл фазу закрывает, но заметно хуже
  специализированного: он общего назначения там, где задача узкая, или закрывает лишь
  часть фазы. Это тоже повод предложить — с прямой формулировкой, чем именно кандидат
  лучше текущего.

Скажи, что нашёл, в таком виде:

> **Фаза «N»:** сейчас закрывает `X` — <чем именно ограничен>.
> **`owner/repo`** (`skill-id`), <N> установок — <что делает и почему здесь лучше>.

Дальше — по `install-flow.md`: там планка доверия, команда установки и правило,
когда ставить самому, а когда спрашивать.

## Жёсткие запреты

- Не выдумывай `skill-id` и `owner/repo` — проверяй по каталогу skills.sh.
- Не называй количество скиллов в библиотеке.
- Не ставь в одну фазу два скилла с одной функцией.
