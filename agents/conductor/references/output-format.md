# Формат вывода: подсветка применённых скиллов

Пользователь должен **видеть**, какие скиллы работают и зачем. Это главная ценность
conductor. Ниже — обязательный формат.

## 1. План перед началом работы

Короткая таблица. Не расписывай на полстраницы.

```
🎼 План

| Фаза | Скиллы | Зачем |
|---|---|---|
| 1. Разбор данных | `explore-data` | понять форму и качество датасета |
| 2. Анализ | `analyze` (метод) · `statistical-analysis` (домен) ⬇ | ответить на сам вопрос |
| 3. Проверка | `verification-before-completion` | подтвердить результат фактами |
```

Пометки:

- **⬇ — скилл установлен в этом заходе.** Пользователь должен видеть, что система
  изменилась, а не только что задача решена.
- У каждого скилла в многоскилловой фазе — его функция в скобках: метод, домен, формат.
- Фаза без скилла помечается `— (делаю напрямую)`. Это честнее, чем притянуть
  нерелевантный скилл.

## 2. Отбивка на каждой фазе

Перед выполнением фазы — одна строка, чтобы было видно переключение:

```
▸ Фаза 2 — применяю `analyze` + `statistical-analysis`: считаю метрику по сегментам
```

Не повторяй содержимое скилла и не пересказывай его инструкции. Одна строка.

## 3. Журнал в конце

```
🎼 Что применил

| Скилл | На какой фазе | Что дал |
|---|---|---|
| `explore-data` | 1 | нашёл 12% пропусков в колонке revenue |
| `analyze` | 2 | падение объясняется одним сегментом |
| `statistical-analysis` ⬇ | 2 | значимость падения подтверждена, p=0.003 |
| `verification-before-completion` | 3 | пересчёт подтвердил цифру |

Установлено: `statistical-analysis` (owner/repo, 4.2K установок) — фаза 2.

Не применял: `build-dashboard` — визуализация не запрашивалась.
```

Строка «Установлено» обязательна, когда что-то ставилось: установка меняет систему
пользователя, и умолчать о ней нельзя.

Строка «не применял» нужна, только если ты всерьёз рассматривал скилл и отказался.
Не перечисляй всё, что не подошло.

## 4. Правила подсветки

- **Только реально применённые.** Не пиши, что применил скилл, если не применял.
  Это ложный отчёт, он обесценивает весь журнал.
- **Не раздувай.** План и журнал — таблицы, не эссе. Работа важнее отчёта о работе.
- **Скиллы в обратных кавычках**: `analyze`, а не /analyze — синтаксис вызова
  зависит от хоста и указывается отдельно.
- **Ничего не нашлось** — так и скажи: «Задача решается напрямую, специализированные
  скиллы не нужны». Это нормальный и частый исход для простых задач.
