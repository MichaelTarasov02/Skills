# Авторинг workflow-скрипта

Справочник по механике. Процедура запуска — в `skills/run-workflow/SKILL.md`.

Источник истины — контракт инструмента Workflow в рантайме. При расхождении с публичной
документацией прав рантайм.

## Скелет

Скрипт — обычный **JavaScript**. Аннотации типов, интерфейсы и дженерики не парсятся.
Тело исполняется в async-контексте, `await` доступен напрямую.

```js
export const meta = {
  name: 'domain-pipeline',
  description: 'Собирает и независимо проверяет документацию по доменам',
  phases: [
    { title: 'Сборка',   detail: 'по агенту на домен' },
    { title: 'Проверка', detail: 'свежим агентом, без контекста сборки' },
  ],
}

phase('Сборка')
const built = await pipeline(domains,
  d => agent(`Собери документацию по домену ${d}`, { phase: 'Сборка', schema: DOC }),
  doc => agent(`Проверь, не видя сборки: ${doc.path}`, { phase: 'Проверка', schema: VERDICT }))
return built.filter(Boolean)
```

`meta` — **чистый литерал**: без переменных, вызовов, спредов и интерполяции. Обязательны
`name` и `description`. Заголовки в `meta.phases` сверяются с `phase()` посимвольно.

## Функции тела

| Функция | Что делает |
|---|---|
| `agent(prompt, opts)` | разворачивает сабагента; со `schema` возвращает валидированный объект, без — строку; `null` при падении |
| `pipeline(items, ...stages)` | гонит каждый элемент через все стадии, **без барьера** |
| `parallel(thunks)` | запускает пачку одновременно, **с барьером** |
| `phase(title)` | группирует агентов в панели прогресса |
| `log(msg)` | строка-нарратор над деревом прогресса |
| `workflow(name, args)` | запускает другой workflow как под-шаг; вложенность — один уровень |

Доступны глобальные `args` (то, что передано в поле `args` вызова) и `budget`
(`total`, `spent()`, `remaining()`).

`opts`: `label`, `phase`, `schema`, `model`, `effort`, `isolation: 'worktree'`, `agentType`.

## Барьер — главное решение

`parallel` ждёт **всех**: общее время равно самому медленному в пачке. `pipeline` не ждёт:
общее время равно самой длинной цепочке одного элемента.

**По умолчанию `pipeline`.** Барьер оправдан, только когда следующая стадия нуждается в
результатах всех предыдущих сразу:

- дедупликация по всему набору до дорогой стадии;
- ранний выход при нуле находок;
- сравнение находок между собой.

Барьером **не является**: «сначала отфильтровать массив» — фильтр делается внутри стадии;
«стадии концептуально разные» — это и есть pipeline; «так код чище».

Признак лишнего барьера: между двумя `parallel` стоит преобразование без межэлементных
зависимостей. Перепиши в `pipeline` с преобразованием внутри стадии.

## Структурированный выход

`opts.schema` (JSON Schema) заставляет сабагента вызвать инструмент структурированного
вывода; валидация происходит на уровне вызова, и при несовпадении модель переспрашивает
сама. Это снимает разбор текста агента регулярками.

Обязательное поле в схеме — способ гарантировать, что агент его не пропустит. Промпт
такой гарантии не даёт: сабагент не видит переписку и не видит, что нашли соседи.

## Пределы

| Предел | Значение |
|---|---|
| Одновременно работающих агентов | `min(16, ядра − 2)`; остальные в очереди |
| Элементов в один `parallel`/`pipeline` | 4096 |
| Агентов за жизнь прогона | 1000 — предохранитель от рекурсии |
| Вложенность `workflow()` | один уровень |

Файловой системы и Node API в скрипте нет: файлы читают и пишут агенты.

**`Date.now()`, `Math.random()` и безаргументный `new Date()` бросают исключение.**
Недетерминированность сломала бы возобновление: тот же скрипт при повторе давал бы другие
промпты и кэш не сошёлся бы. Нужна метка времени — передай через `args`. Нужна
вариативность — вари промпт по индексу элемента.

## Возобновление — и способ отладки

Каждый прогон получает `runId`. Повторный вызов с `resumeFromRunId` возвращает **самый
длинный неизменённый префикс вызовов `agent()` из кэша мгновенно**; первый изменённый или
новый вызов и всё после него исполняется заново. Тот же скрипт и те же аргументы дают
стопроцентное попадание.

Отсюда приём отладки: правишь одну фазу, перезапускаешь с тем же `runId` — платишь
стоимость только изменённого. Конвейер на миллион токенов правится по фазе почти даром.

Прогон прерван — возобновляй по `runId`. Перезапуск без него оплачивает всё заново.

## Журнал

Каждый прогон пишет `journal.jsonl` в каталог транскрипта с фактическими возвращаемыми
значениями каждого агента. Конвейер вернул пустоту или чушь — ответ там, а не в догадках.

## Сохранённый workflow

Скрипт в `.claude/workflows/` проекта вызывается **по имени**, а не по пути, и становится
частью проекта. Разовый скрипт из сессии сохраняется автоматически, и его путь возвращается
в результате вызова — перенеси оттуда то, что стоит повторять.

## Приёмы качества

Выбирай по задаче, комбинируй свободно:

- **Состязательная проверка.** N независимых скептиков на находку, каждому предписано
  **опровергнуть**. Отсекает правдоподобное-но-неверное.
- **Разные линзы.** Когда находка может отказать по-разному, дай проверяющим разные углы
  (корректность, безопасность, воспроизводимость) вместо N одинаковых.
- **Панель судей.** N независимых попыток с разных сторон, параллельная оценка, синтез из
  победителя с прививкой лучших идей проигравших.
- **Цикл до сухого.** Для находок неизвестного объёма: спавнить искателей, пока K раундов
  подряд не вернут ничего нового. Дедуплицируй против **всех виденных**, а не против
  подтверждённых, иначе отклонённое возвращается каждый раунд и цикл не сходится.
- **Критик полноты.** Финальный агент: что осталось непокрытым — модальность, непроверенное
  утверждение, непрочитанный источник.
- **Ограничения вслух.** Урезал охват (топ-N, без ретраев, выборка) — скажи `log()`, что
  отброшено. Молчаливое усечение читается как полное покрытие.
