# 🎼 Conductor

Подбирает нужные скиллы под твой запрос **до** начала работы, выполняет её и показывает,
какой скилл применён на каждой фазе.

## Быстрый старт

```bash
claude plugin marketplace add MichaelTarasov02/Skills
claude plugin install conductor@skills
```

**Перезапусти Claude Code** (или `/reload-plugins`) — иначе скиллы не подхватятся в
текущей сессии.

Дальше просто опиши задачу:

```
/conductor:suggest-skills Проанализируй падение выручки в Q3 и покажи причины
```

## Скиллы

| Скилл | Когда использовать | Что делает |
|---|---|---|
| `suggest-skills` | Запрос понятен, нужно просто сделать хорошо | Разбирает задачу на фазы → обозревает библиотеку по каталогу и графу → подбирает 1–3 скилла на фазу → доустанавливает недостающее → выполняет с подсветкой применённого |
| `prompt-before-implementation` | Запрос сырой, надиктован, сложный или дорогой в ошибке | Строит карту контекста, пишет промпт из **пяти обязательных фаз** (брейншторм → план → имплементация → тестирование → отчёт), показывает и выполняет |

Флагов нет — оба работают от обычного текста запроса.

| `run-workflow` | Задача не помещается в один контекст: много однотипных единиц, нужна независимая проверка | Разведывает очередь вживую → пишет JS-скрипт конвейера → разворачивает сабагентов по фазам → возвращается с готовым результатом |

**Как выбрать:** ясная задача → `suggest-skills`. Мутная или многоэтапная →
`prompt-before-implementation`. Не помещается в одну голову → `run-workflow`.
Лишняя фаза написания промпта на простой задаче только
замедлит.

## Как выглядит работа

```
🎼 План
| Фаза | Скилл | Зачем |
|---|---|---|
| 1. Разбор данных | explore-data | понять форму и качество датасета |
| 2. Анализ | analyze | ответить на сам вопрос |
| 3. Проверка | verification-before-completion | подтвердить результат фактами |

▸ Фаза 1 — применяю explore-data: профилирую датасет
...

🎼 Что применил
| Скилл | Фаза | Что дал |
```

## Если нужного скилла нет

Conductor не только пользуется тем, что есть, — он доустанавливает недостающее. Повод
возникает в двух случаях: скилла под фазу нет вовсе, либо установленный закрывает её
заметно хуже специализированного.

Что будет дальше, решает **планка доверия**:

| Кандидат | Что делает conductor |
|---|---|
| ≥ 1000 установок · аудиты чистые · только текст (`SKILL.md` + `references/`) | ставит сам, читает установленный скилл и продолжает работу |
| меньше установок, незнакомый владелец, Fail/Warn в аудите, есть `scripts/`, `hooks/`, `.mcp.json`, нужен токен | показывает находку и ждёт твоего ответа |

```
Фаза «монтаж видео»: сейчас закрывает `content-creation` — общего назначения, монтажа не знает.
remotion-dev/skills (remotion-best-practices), 12K установок — программный монтаж на React.
⬇ поставил, продолжаю.
```

В обоих случаях он возвращается ровно туда, где остановился, и продолжает — не начинает
заново. Каждая установка попадает в итоговый журнал. Отказался один раз — в этой сессии
больше не предложит.

## Конвейер: когда задача не помещается в один контекст

`run-workflow` разворачивает сабагентов по фазам и возвращается с готовым результатом.
Вызов самого скилла — достаточное согласие на оркестрацию, отдельное слово-заклинание
не нужно.

Чем платишь, честно: конвейер — это фан-аут. Замеренный прогон на четыре домена —
**11 агентов, 1.1 млн токенов, 13 минут**. Стоимость называется до запуска.

```
/conductor:run-workflow Прогони документацию по всем доменам: сборка, потом независимая проверка
```

Что делает скилл сверх запуска:

- **Разведка вживую до оркестрации.** Скрипт не читает файлы — очередь работы собирается
  обычными инструментами заранее.
- **`pipeline` по умолчанию.** Барьер `parallel` ждёт всех и тратит время быстрых агентов;
  он берётся, только когда стадии правда нужны все результаты сразу.
- **Возобновление вместо перезапуска.** Прервалось или поправил скрипт — `resumeFromRunId`
  вернёт неизменённый префикс из кэша. Перезапуск без него платит за всё заново.
- **Отчёт из журнала прогона**, а не из замысла.

Прогон, который понадобится снова, переезжает в `.claude/workflows/` проекта и дальше
вызывается по имени.

## Установка для Codex

Codex работает по стандарту [Agent Skills](https://agentskills.io) и ставит скиллы,
а не плагины. Слинкуй их в общую папку `~/.agents/skills/` — её читают оба хоста:

```bash
git clone https://github.com/MichaelTarasov02/Skills.git ~/team-skills
mkdir -p ~/.agents/skills
ln -s ~/team-skills/agents/conductor/skills/suggest-skills ~/.agents/skills/suggest-skills
ln -s ~/team-skills/agents/conductor/skills/prompt-before-implementation ~/.agents/skills/prompt-before-implementation
```

Линкуй, а не копируй — тогда `git pull` обновляет установленное. Начни новую сессию Codex.

Вызов в Codex — через `$`: `$suggest-skills`, `$prompt-before-implementation`.

## Устройство

| Файл | Что содержит |
|---|---|
| `references/prompt-blueprint.md` | Каркас генерируемого промпта: пять обязательных фаз, восемь разделов, формат контекстной карты |
| `references/skill-selection.md` | Где искать скиллы, как подбирать и дедуплицировать, режим пробела |
| `references/output-format.md` | Формат плана, отбивок на фазах и итогового журнала |

Оба скилла читают одни и те же правила из `references/` — правило живёт в одном месте,
поэтому не разъезжается между скиллами.

## Проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Скилл не появился | Не перезапустил агента | Рестарт или `/reload-plugins` |
| Conductor не подбирает скиллы | Задача простая | Это нормально: он честно скажет, что скиллы не нужны |
| Подбирает лишнее | Запрос слишком общий | Сформулируй конкретнее либо возьми `prompt-before-implementation` |
| Не видит твоих скиллов | Библиотека вне известных путей | Запусти агента из корня репозитория со скиллами или слинкуй их в `~/.agents/skills/` |
| Плагин не грузится | Битый манифест | `claude plugin validate <путь>` |

Диагностика:

```bash
claude plugin list
claude plugin details conductor@skills
```
