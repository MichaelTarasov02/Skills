# Методология улучшения агента

Как дополнять и улучшать уже построенного агента, не сломав то, что работает.
Источник принципов: `writing-great-skills` (предсказуемость, иерархия информации,
прогрессивное раскрытие, ведущие слова, режимы отказа) + официальная документация
Claude Code по скиллам и плагинам.

## Главный принцип: предсказуемость

Скилл существует, чтобы вырвать детерминизм из стохастической системы. Улучшение —
это **рост предсказуемости**: агент каждый раз идёт одним и тем же процессом. Любая
правка, которая делает поведение менее предсказуемым (размытый критерий, дубль правила,
лишний путь), — это регресс, даже если добавляет «возможностей».

## Что вообще можно улучшать (уровни)

От дешёвого и безопасного к дорогому и рискованному:

1. **Описание (`description`)** — самый дешёвый и частый выигрыш. Скилл «не срабатывает»
   почти всегда лечится здесь: ведущее слово вперёд, по одному триггеру на ветку,
   убрать синонимы-дубли. Не трогая тело, чинишь автовызов.
2. **Критерии завершения шагов** — размытый критерий («сделай список изменений») рождает
   преждевременное завершение. Заостри до проверяемого («каждый изменённый файл учтён»).
3. **Прунинг тела** — удали no-op-предложения (проверь каждое в изоляции: несёт ли оно
   смысл?), схлопни дубли в единый источник истины, замени растянутые фразы ведущими
   словами. Обычно скилл улучшается **удалением**, а не добавлением.
4. **Прогрессивное раскрытие** — если `SKILL.md` разросся (> ~5k слов), вынеси детали в
   `references/`, оставив в теле только процедуру. Правило: смысл живёт либо в `SKILL.md`,
   либо в reference — никогда в обоих.
5. **Новые reference/скрипты** — добавь `references/` под новую предметную область или
   `scripts/` под детерминированную операцию, которую агент переписывает каждый раз.
6. **Новый скилл или агент** — самый дорогой шаг. Дели, только когда рез оправдан:
   у новой функции есть своё ведущее слово-триггер, ИЛИ длинный хвост шагов провоцирует
   спешку на текущем. Иначе получишь два скилла с одной функцией — это ошибка дизайна.

Всегда начинай с самого дешёвого уровня, который закрывает проблему. Не переписывай
скилл целиком, если хватает заострить один критерий.

## Диагностика: с чего начать улучшение

Прежде чем править, определи **режим отказа** (по `writing-great-skills`):

| Симптом | Режим отказа | Дешёвое лечение |
|---|---|---|
| Заканчивает шаг недоделанным | Преждевременное завершение | заострить критерий завершения; если он неустраним-размытый и спешка видна — спрятать хвост шагов делением |
| Одно и то же правило в двух местах | Дублирование | схлопнуть в единый источник истины |
| Скилл оброс мёртвыми абзацами | Осадок (sediment) | прунинг: удалять, а не переписывать |
| Не срабатывает автоматически | Слабое `description` | ведущее слово вперёд, живые триггеры |
| Срабатывает слишком часто | Широкое `description` | сузить, либо `disable-model-invocation` для ручного |

Не начинай с «давай перепишем» — начни с диагноза конкретного симптома.

## Границы: что улучшение НЕ делает

- **Не меняет назначение агента.** Улучшение усиливает то, что агент уже делает.
  Смена задачи — это новый агент, а не правка.
- **Не ломает работающее.** Каждая правка сохраняет прежнее поведение на прежних входах.
  Если правишь фазу — прогони старый вход и убедись, что результат не поехал.
- **Не раздувает.** Добавил абзац — найди, что удалить. Скилл без дисциплины прунинга
  обрастает осадком по умолчанию.
- **Не плодит дубли функций.** Новый скилл только если у него своя функция и свой триггер.

## Обязательное локальное обновление (иначе смысла нет)

Улучшение бесполезно, пока пользователь не может им пользоваться. После правок:

1. **Правки `SKILL.md`** подхватываются вживую — рестарт не нужен.
2. **Новый скилл / новый reference / правки `hooks`, `agents`, `.mcp.json`** живьём
   НЕ подхватываются. Нужен `/reload-plugins` или рестарт Claude Code; для Codex —
   новая сессия.
3. **Подними `version`** в `.claude-plugin/plugin.json`. Это ключ кэша: без бампа
   `claude plugin update` у пользователя (и у команды) ответит «уже последняя»,
   и правки не приедут. Патч-правка → +0.0.1, новый скилл → +0.1.0.
4. Если агент установлен из маркетплейса — после бампа версии выполнить update и рестарт.
   Если `@skills-dir` (папка в `~/.claude/skills/` или симлинк на репо) — `/reload-plugins`.
5. **Codex**: если у скиллов есть симлинки в `~/.agents/skills/` или `~/.codex/skills/` —
   новый скилл нужно долинковать, существующие подтянутся сами (симлинк на ту же папку).

Локальное обновление — не опция, а часть работы. Улучшение без него не завершено.

## Порядок правок (безопасная последовательность)

1. Диагноз симптома → выбор минимального уровня.
2. Правка в единственном источнике истины.
3. Прунинг: на каждый добавленный абзац — поиск, что удалить.
4. Локальное обновление (версия + reload + Codex-линки).
5. Верификация фактами: валидатор, парсинг фронтматтера, сухой прогон старого входа.
