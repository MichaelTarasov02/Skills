# Промпт: превратить рабочий проект в общекомандного агента

Скопируй всё, что ниже разделителя, в Claude Code (или Codex), открытый **в папке твоего проекта**.
Заполни блок «Вход» — остальное промпт сделает сам.

---

## Вход — заполни перед запуском

```
ПРОЕКТ:            <путь к папке проекта, или «текущая папка»>
ЧТО ЭТО:           <одна фраза: что делает твой инструмент>
ЦЕЛЕВОЙ РЕПОЗИТОРИЙ: <url гит-репозитория команды, куда пушим агента>
ВЕТКА:             <ветка для пуша, если не main>
КТО БУДЕТ ПОЛЬЗОВАТЬСЯ: <кто в команде и в каких редакторах работает>
```

---

# Задача

Преврати мой проект в **агента** — набор скиллов, которым сможет пользоваться вся команда
из любого редактора, — и выложи его в наш репозиторий.

Работай по фазам. Каждая заканчивается строкой **«Готово, когда»** — выполни её условие,
прежде чем идти дальше. После каждой фазы печатай короткую отбивку и продолжай сам.
Остановись только на Фазе 2: там ждёшь моего подтверждения.

## Что считается результатом

Коллега клонирует репозиторий, выполняет одну команду из README и через минуту вызывает
агента у себя — в Cursor, VS Code, Claude Code или Codex, без правки чужих путей и без
моих ключей.

---

## Ключевой факт об архитектуре — прочти до начала

**Скиллы переносимы между редакторами. Обёртка-плагин — нет.**

Стандарт Agent Skills (папка + `SKILL.md` с `name` и `description`) читают Claude Code,
Codex, Cursor, VS Code/Copilot, Gemini CLI, JetBrains Junie и другие. А манифест
`.claude-plugin/plugin.json`, хуки и маркетплейс — механика только Claude Code; Cursor и
Copilot про них не знают.

Поэтому репозиторий строится **скиллами вперёд**, а плагин добавляется сверху как
необязательный слой для тех, кто сидит в Claude Code.

Где какой хост ищет скиллы (проверено по официальным докам):

| Хост | Проектные | Пользовательские |
|---|---|---|
| Cursor | `.agents/skills/`, `.cursor/skills/` | `~/.agents/skills/`, `~/.cursor/skills/` |
| VS Code / Copilot | `.github/skills/` | `~/.copilot/skills/`, `~/.agents/skills/` |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` |
| Codex | `.codex/skills/` | `~/.codex/skills/` |

**`.agents/skills/` — общий знаменатель.** Cursor и Copilot читают его напрямую, и оба
дополнительно подхватывают `.claude/skills/`. Клади скиллы в `.agents/skills/`, остальные
пути закрывай симлинками.

Инструкции уровня репозитория держи в **`AGENTS.md`** — это кросс-тульный стандарт
(Linux Foundation), его читают Codex, Cursor, Copilot, Gemini CLI, Aider, Windsurf, Zed.
`CLAUDE.md` при необходимости делай симлинком на него, чтобы правда жила в одном файле.

---

## Фаза 0. Поставь правила

Агент собирается по правилам нашей команды, а они лежат в плагине `agent-forge`:

```bash
claude plugin marketplace add MichaelTarasov02/Skills
claude plugin install agent-forge@skills
```

Затем перезапусти Claude Code (или выполни `/reload-plugins`).

Работаешь в Codex или Cursor — склонируй репозиторий и читай напрямую
`agents/agent-forge/SKILL.md` вместе с его папкой `references/`; процедура та же.

**Готово, когда:** `claude plugin list` показывает `agent-forge`, либо файл
`agents/agent-forge/SKILL.md` открыт и прочитан.

## Фаза 1. Разбери проект

Примени скилл **`analyze-project`** из `agent-forge` — он работает только на чтение и
ничего не создаёт.

Пройди по проекту и собери **Project Map**:

- дерево репозитория на 2–3 уровня, `README`, `AGENTS.md` / `CLAUDE.md`
- процедуры, которые повторяются: что коллеги делают руками одинаково раз за разом
- существующие промпты и воркфлоу, если они где-то записаны
- скрипты и вызовы API, которые инструмент реально выполняет
- примеры вывода — они показывают настоящий контракт результата

Затем ответь на три вопроса прямо:

1. **Что здесь становится скиллом, а что остаётся кодом?** Скилл — это процедура и
   решения. Детерминированный вызов API остаётся скриптом, который скилл запускает.
2. **Не делает ли это уже готовый инструмент?** Для Jira существует официальный
   MCP-сервер Atlassian. Проверь, покрывает ли он задачу, и скажи честно, если наш бот
   его дублирует, — тогда агент нужен тоньше, только вокруг того, чего в MCP нет.
3. **Что мешает поделиться?** Ищи в коде и промптах: абсолютные пути в чей-то домашний
   каталог, токены и ключи, личные аккаунты, зашитые названия проектов Jira. Каждое такое
   место выпиши отдельным списком — на Фазе 3 оно уедет в конфиг.

**Готово, когда:** каждая найденная повторяемая процедура выписана вместе с файлом, где
живёт сегодня, и список блокеров шеринга составлен.

## Фаза 2. Отдай на проверку человеку — и остановись

Покажи результат и **дождись ответа**. Дальше без подтверждения не иди.

```
## Что за проект
<две фразы>

## Найденные повторяемые процедуры
| Процедура | Где живёт сейчас | Как часто | Кандидат в скилл |

## Предлагаемый агент
Имя: <kebab-case>
Назначение: <одна фраза>

| Скилл | Ответственность | Вход | Выход |

Нужны ли отдельные подагенты: <да + обоснование изоляцией контекста | нет>
Нужен ли скилл настройки под пользователя: <да/нет — что именно будет настраиваться>

## Блокеры шеринга
| Что | Где | Как убираем |

## Уже готовое, что трогать не нужно
## Вердикт
<Паковать / Не стоит / Частично — с обоснованием>
```

Закончи ровно одним вопросом:

> Всё верно? Что поправить в списке скиллов, прежде чем я начну собирать?

**Готово, когда:** человек ответил и его правки внесены в список скиллов.

## Фаза 3. Собери агента

Запусти основной скилл **`agent-forge`** и пройди его фазы. Список скиллов из Фазы 2 уже
согласован — подставляй его в форму, а не выдумывай заново.

Отдельно проследи за тремя вещами:

- **Фаза прунинга `agent-forge` обязательна.** Она вычищает из сгенерированных скиллов
  размытые критерии, слабые указатели и предложения, которые ничего не меняют. Пропуск
  этой фазы даёт валидный плагин, который агент игнорирует.
- **Ключи уезжают в конфиг.** Каждый блокер из Фазы 1 закрывается скиллом `setup-<агент>`,
  который расспрашивает нового пользователя и пишет его собственный файл настроек. Токены
  Jira в теле скилла делают агента непередаваемым.
- **Код остаётся кодом.** Рабочие вызовы API кладутся в `scripts/` внутри скилла, а скилл
  описывает, когда и с какими аргументами их звать.

**Готово, когда:** у каждого согласованного скилла есть `SKILL.md`, чей фронтматтер
парсится с непустыми `name` и `description`, ни в одном файле нет заглушек, и таблица
вырезанного на прунинге выписана.

## Фаза 4. Разложи под все редакторы

Собери в репозитории такую структуру:

```
<repo>/
├── AGENTS.md                  # инструкции уровня репозитория, кросс-тульный стандарт
├── CLAUDE.md -> AGENTS.md     # симлинк, чтобы правда жила в одном файле
├── .agents/skills/            # ИСТОЧНИК ИСТИНЫ — сюда кладутся скиллы
│   └── <skill>/SKILL.md
├── .claude/skills/            # симлинк на ../.agents/skills
├── .github/skills/            # симлинк на ../.agents/skills  (VS Code / Copilot)
├── .claude-plugin/            # необязательный слой только для Claude Code
│   └── plugin.json
└── README.md
```

Каждый `SKILL.md` обязан оставаться корректным **без** полей, которые понимает только
Claude Code (`allowed-tools`, `context: fork`, `agent`, `model`). Cursor и Copilot их
игнорируют — прочти каждый скилл так, будто этих строк нет, и убедись, что смысл цел.

Обязательными везде остаются только `name` и `description`. Держи скилл рабочим на этих
двух полях: всё остальное — необязательные расширения, и поддержка у них разная от хоста
к хосту (`paths` и `disable-model-invocation` документированы у Cursor, но полагаться на
них как на общий минимум не стоит).

**Готово, когда:** `find -L .agents/skills .claude/skills .github/skills -name SKILL.md`
находит один и тот же набор файлов через все три пути.

## Фаза 5. Проверь, запушь, опиши

**Сначала проверка, потом пуш.**

1. `claude plugin validate <путь>` — покажи вывод, повторяй, пока не станет чисто.
2. Фронтматтер каждого `SKILL.md` парсится, `name` совпадает с именем папки.
3. **Сухой прогон:** возьми одну настоящую задачу, которую бот решал раньше, прогони
   агента целиком и сравни результат с тем, что бот выдавал. Пройденный валидатор ещё не
   доказывает, что агент делает свою работу.
4. Проверь, что в диффе нет секретов: `git diff --staged | grep -iE 'token|secret|api[_-]?key|password'` должен молчать.

Затем пуш в целевой репозиторий, в ветку из блока «Вход». Работу на чужой ветке и
`--force` не применяй.

`README.md` пиши так, чтобы первый экран давал понять и запустить за полминуты:

- что агент делает, одной фразой
- **установка по редакторам** — отдельная короткая инструкция для Cursor, VS Code,
  Claude Code и Codex, каждая проверена запуском
- таблица скиллов: **когда применять** (не что внутри — читатель выбирает, а не изучает)
- что нужно настроить под себя и какой командой
- что делать, если скилл не срабатывает

**Готово, когда:** каждая команда из README выполнена и дала то, что README обещает,
а ссылка на пуш приведена.

## Финальный отчёт

- имя агента и что он делает
- скиллы с назначением
- **что вырезал прунинг** — таблицей
- что уехало в конфиг вместо жёсткой зашивки
- результаты проверок Фазы 5 с выводом команд
- ссылка на коммит и три команды, которые коллега может выполнить прямо сейчас
- что осталось незакрытым и почему

## Правила на всю работу

- **Подтверждай, потом называй.** Любой файл, путь и команда в отчёте существуют — проверь
  и только затем пиши.
- **Упаковка сохраняет поведение.** Оборачивай логику так, как она работает сегодня;
  идеи улучшений собери отдельным списком и отдай в конце.
- **Один скилл — одна ответственность.** Два скилла с одной работой сливаются на Фазе 2.
- **Пиши файлы целиком**, готовыми к запуску как есть.
- **Останавливайся на Фазе 2** и жди человека. Остальные фазы иди подряд.
